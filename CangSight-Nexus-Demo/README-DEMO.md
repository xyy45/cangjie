# CangSight Nexus 演示版

独立目录，基于 V1.1 固定源码 `3f05f6e`。当前演示入口默认使用 DeepSeek 生成修复建议和完整仓颉源码，随后执行真实 MCP、仓颉策略、构建和测试；人工接受后导出同版本证据包。

## 启动

```bash
cd /Users/jxy/Desktop/CangSight-main/CangSight-Nexus-Demo
python3 -m nexus.demo.app --port 8877
```

也可双击 `启动演示.command`。打开 <http://127.0.0.1:8877>。保持标题、按钮、数据和短状态；详细需求与修复建议在弹窗中显示。

首次部署复制 `.env.example` 为 `.env`，填写 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。本机配置已保存；不要覆盖。Key 只在服务端使用，`.env` 不进入交付压缩包。默认模型 `deepseek-flash`，模型是否可用以配置账号实际响应为准。

本机已复用相邻 V1.1-local 的 SDK/stdx，并在本工程编译策略。其他机器需 Python 3.12，`python3 -m pip install -r requirements.lock`。实际执行目前支持固定 macOS ARM64 环境，执行 `python3 scripts/install_runtime.py`、`python3 scripts/build_policy.py` 并安装固定 MacOSX15.4 开发 SDK。源码 ZIP 不含 SDK、Key、操作者凭据或运行数据库。

## 源码分析

左侧点击“源码分析”。三个登记样例来自真实课题组工具调用，切换时读取与源码摘要匹配的快照，标签为“样例快照”；点击“重新分析”才产生新的三次工具请求。

- 直线依赖：有效切片与DDG；循环／跨函数样例：DDG有效，现有切片引擎内部报错，页面显示“部分结果”。
- 循环／跨函数日志中已有的文本切片现可本地解析恢复，分别展示4／10个变量和提示色高亮；来源标注“日志解析恢复”，原工具失败状态保留。下载包含原始证据及独立派生JSON；这些恢复数据不会自动加入模型上下文。见[日志切片恢复验收](docs/demo/slice-recovery-verification.md)。
- 选择切片变量，高亮实际返回的源码行；选择图节点关联有明确行号的源码，支持缩放和滚动。
- 上传单个UTF-8 `.cj`，最大64KiB／1000行，预览后勾选“发送至课题组 MCP”并点击“分析”。新文件立即清空旧结果；上传失败不会回退固定样例。
- 实际调用 `sympas_slice`、`sympas_dep_graph`、`ast_symbol_extractor`，使用当前课题组HTTP工具入口；每工具一次 POST，单次 POST 总期限45秒、响应最大2MiB，无自动重试。图工具同时请求 `Ddg,Cg` 和 `dot,svg`；随后最多一次同源 SVG GET，独立期限8秒、最大2MiB。
- “证据”查看输入摘要、时间、观察状态和限制；下载包含原始源码、逐工具原始响应、确切结果文件及SHA-256清单。
- 私有分析按当前浏览器会话归属；无需配对，服务重启后保留会话，可在“最近分析”恢复文件、结果并再次分析。恢复仅读取，不会重发请求；再次分析需明确点击按钮。

服务端可通过本机 `.env` 的 `CANGSIGHT_ANALYSIS_URL` 和可选 `CANGSIGHT_ANALYSIS_TOKEN` 配置已允许的课题组地址；默认入口无需token。不会向该服务传递DeepSeek密钥，也不在本机运行上传代码。此处结构线索不等同于完整AST、类型检查或行为正确性证明。当前复杂语法、切片行准则精度和图标签简化存在已观测限制。

验证结果见[源码分析验收记录](docs/demo/analysis-verification.md)。登记样例及脱敏原始证据位于 `fixtures/analysis/`；用户上传和私有结果只存在 `.runtime/demo-workbench/analysis/`，不进入源码ZIP。

分析结果下方新增“函数调用图 Cg · SVG”：打开 MCP 原生 SVG 或下载本地保存的原文件，证据 ZIP 也包含它。SVG 绑定当前源码摘要和分析记录；静态切片失败不影响已取得的 SVG。旧快照没有 SVG，需要点击“重新分析”。修复依据、影响对比的分析详情也支持同一入口。查看[调用图 SVG 验证记录](docs/demo/callgraph-svg-verification.md)。

## 九个案例

六个修复案例均接入同基线的真实MCP分析：按当前任务允许修改的生产文件收集，最多三文件／九次工具请求，有效结构进入DeepSeek上下文，页面“分析依据”显示模型引用并打开只读切片。失败或空结果不作为有效依据，超出上下文预算的结果保留原始证据。仓颉策略卡片和详情读取实际请求/决定/动作后果；待审阅时可执行明确标记的“未批准导出探测”，实际返回NeedApproval且不执行导出。早期单案例验收见[历史记录](docs/demo/bridge-verification.md)，本轮六案例实测见[结构化反馈与覆盖验证](docs/demo/structured-feedback-verification.md)。

| 组 | 案例 | 实际行为 |
| --- | --- | --- |
| 订单 | 数量、价格上界、优惠门槛 | 模型根据各项目上下文生成建议和源码，冻结测试独立验证 |
| 跨文件 | 校验与计费、优惠与结算、库存与扣减 | 每个项目包含两处协同缺陷，允许修改两份生产 `.cj` |
| 策略 | 测试保护、配置保护、路径越界 | 固定受控提案，经真实原生策略和 MCP 契约拒绝，候选写入数为零 |

点击案例只加载源文件，不调用模型。六个修复案例点击“开始”后，执行最多三轮 CEGIS 修复：每轮最多一次 HTTP 模型请求、6000 输出 Tokens，总时限 480 秒。候选真实构建或测试失败后，将完整修改、diff、失败诊断和剩余预算交给 DeepSeek，再从同一基线生成下一候选；最多 18000 输出 Tokens。模型请求超时、返回截断、格式不合规或验证环境未知时停止，不自动重放；重复候选或连续相同失败也停止。通过后等待人工审阅。旧任务已花费的调用预算不会因升级重置。详见 [CEGIS 验证记录](docs/demo/cegis-verification.md)。

新失败轮次会显示“验证反例”：从真实仓颉测试日志提取用例、可确认的字面量输入、预期和实际结果，并保留日志引用及诊断字符位置；同一份反例进入下一轮模型请求。需求关联仅标为测试套件映射，缺失字段显示未提供；编译失败保留诊断日志。首轮即通过时不产生失败反例卡片，旧记录不补写。

## 上传单文件修复

侧栏“上传文件修复”选择 `.cj` 并填写预期行为，点击“读取函数”，选择待测函数，填写2至12组JSON输入与预期输出（target和regression至少各一项），确认发送许可后进入工作台。此时尚未调用模型；点击“开始”才执行MCP、DeepSeek和CEGIS。确认示例冻结，模型只能改生产源码；通过后仍需人工接受才能导出。

第一版支持Int64／Bool参数与返回值的普通函数、局部变量、算术／比较／逻辑、条件、while及参数类型匹配的同文件调用；最多4参数、16函数。暂不支持导入、类、宏、数组、字符串、外部调用、函数重载和标准输入输出预留名。只接受LF／CRLF，不支持嵌套块注释。源码与候选都经过受限检查，再由固定SDK真实编译测试；不支持的代码会明确拒绝，仍可使用原有“源码分析”入口。

无包声明时，工程副本前置 `package uploadedrepair`；原始字节单独保留并随交付导出。上传、需求和任务按浏览器会话隔离，可从本会话上传记录或任务记录恢复。只验证确认示例，不代表任意输入正确。可使用 [上传示例](examples/upload_order_functions.cj) 与 [示例测试JSON](examples/upload_order_functions.examples.json)。详见 [上传修复验收](docs/demo/upload-repair-verification.md)。

“修复建议”显示与当前候选同一个模型响应的中文摘要及逐文件建议；修改后的代码直接取自实际候选。模型不能修改测试、配置或目录范围。通过测试只代表已冻结用例覆盖的行为，不等于全部语义正确。

## 选行切片与修复影响对比

源码分析支持点击行或输入行号，按实际选择请求后向切片；历史、证据和下载保存目标行。切换目标时会区分旧结果与待请求准则。

真实候选的“影响对比”先显示本地源码差异与函数文本位置，明确生成后才调用MCP分析两侧版本。可以查看每侧原图／切片并下载绑定源码摘要的证据。工具失败或空图如实展示；不增加模型调用，也不自动接受候选。详见 [验证记录](docs/demo/precision-impact-verification.md)。

## 来源和本机运行

| 标签 | 来源 |
| --- | --- |
| DeepSeek | 本次真实模型响应，实际 SDK 验证，等待人工接受 |
| 原生 | 本次受控策略探测，无模型调用、不运行修复与交付 |
| 回放 | 历史 AI 订单修复或历史策略探针，非本次运行 |
| 模拟 | 历史跨文件预置流程，非实际构建测试 |
| 规则 | 显式 `--provider rule` 启动的旧订单固定规则模式，不计 AI 修复 |

默认“生成”；只有原有三个历史案例可以切换“回放”。离线回放无需 SDK 或模型；新案例没有固定修改后代码和预置成功结果。

演示服务无需操作者配对或密钥：打开页面即可开始修复、分析和查看记录，启动时不再生成或读取配对密钥。服务仅监听本机，保留 Host／来源检查、CSRF、浏览器会话归属、单写者实例锁、候选审批绑定和导出检查。通过验证后仍需人工接受。原底座工作台默认继续使用操作者凭据。详见 [免配对验证记录](docs/demo/direct-access-verification.md)。
