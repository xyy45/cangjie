## V1.1 Native 当前演示流程

本流程是给实际操作者的执行说明，不是“已完成真人演示”的证明。Docker不引入，也不作为前置条件。当前已验证范围与原始输出见docs/v1.1/native-security-fix-report.md。

1. 按runbook检查固定SDK、Policy、环境配置并启动正式Native服务。先确定是否使用真实模型；新的模型调用需要相应费用授权，不能因演示脚本存在就自动执行。
2. 在录屏之外，通过可信本机终端读取本机.operator-key并授权浏览器。不要录制终端凭据、填写过程、开发者工具请求体、.env或真实API Key。重启后必须重新配对，不能用开发者会话代替成员自己的会话。
3. 可先用另一个未配对会话验证任务/候选读取和审批/导出被403拒绝；这一步不调用模型。配对成功后显示原工作台，不把“配对成功”当作“修复成功”。
4. 选择登记订单案例，准备需求，检查三条冻结规则和允许文件范围，然后确认。真实模型任务仍走已有MCP-CEGIS、原生Policy及cjpm，最多三候选；不用手写内容替代模型来源。
5. 展示缺陷基线的10通过/1失败、真实候选diff和当前同稿build/test/需求投影；仅必需检查全部通过时才能接受。首候选成功就进入审阅，不为演示强造失败轮次。
6. 由实际操作者明确接受或拒绝当前候选。接受后通过MCP完整导出，下载核对project/evidence、候选/需求/计划/批准与归档摘要；标明操作者身份来源。拒绝/取消不自动重新调用模型。
7. 执行独立标注的D保护探针，展示原生Policy与MCP各自拒绝证据、文件不变；D不是模型主动发起的攻击。检查原Sympas参考未变。
8. 如需演示重启，先确认没有执行中的任务并停止自己的服务；重启重新配对，查看历史与失效提示。失效不能通过复用旧批准、修改历史记录或自动重发付费请求来修复。

无需付费的技术展示可以运行完整离线/SDK测试，或展示明确标注的“历史真实模型提案在当前执行器重验证”记录。它们不能被命名为本轮新LIVE生成，也不等于真人操作视频或独立成员复现。
