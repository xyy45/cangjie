# CEGIS 迭代修复验证记录

日期：2026-10-20。

## 当前行为

六个已注册修复案例共用同一循环：需求与基线源码（主案例还含绑定源码的真实课题组 MCP 分析）→ DeepSeek 修复建议与完整修改 → 路径、原文件哈希和原生策略检查 → 独立候选副本 → 本地 MCP 执行固定仓颉 SDK 构建／测试 → 失败反馈进入下一轮。

最多三轮，每轮最多一次模型请求、6000 输出 Tokens，任务总时限 480 秒。最多 18000 输出 Tokens；输入 Tokens 和费用随上下文增加。HTTP 超时／结果未知、无效 JSON、输出截断或工具环境未知时停止，不自动重放请求。重复候选、连续相同失败或候选预算耗尽也停止并记录原因。

每一轮从同一不可变基线创建候选，因此后续模型必须给出累积修复后的完整文件，并使用原始 before_hash。失败反馈含前候选 ID／树摘要、完整编辑、diff、失败检查、诊断片段、需求 ID 和剩余预算。后续请求只有在上一调用成功、候选和持久化失败反馈一致时才获准；SQLite 事务保留每轮唯一的调用预约，进程重启不会恢复已花费额度。历史单次调用版本的预约仍视为已花费，不迁移为额外调用资格。

前端新增 CEGIS 面板：每轮摘要、构建／测试状态、Tokens、轮次选择、失败诊断与停止原因。选择轮次同时切换建议、源码和检查；“跟随最新”回到当前候选。历史候选不能接受或拒绝，异步迟到响应不能覆盖新选择。

自动应用仅发生在独立候选副本。构建与测试通过后停在人工审阅，保留接受／拒绝和导出的原有审批链。
