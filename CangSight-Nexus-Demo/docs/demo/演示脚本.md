# 五分钟演示

优先使用10月20日的“校验计费修复”真实记录：分析依据显示2文件、3项有效依据、模型引用2项；查看fee.cj真实切片，再回工作台看两文件diff和9项测试。策略“详情”显示实际Allow；“未批准导出探测”显示NeedApproval及动作未执行。随后展示测试保护Deny/零候选写入。该次主案例DDG为空，数量切片失败，均如实展示。[本轮验收与截图](bridge-verification.md)。

1. 启动演示服务，默认“生成”，打开页面即可点击“开始”，无需配对。
2. 从“任务记录”恢复已完成的 DeepSeek「校验计费修复」，这不会再次请求模型。本次联调实际修改两文件，构建和9项测试通过，4965 Tokens，停在待审阅。
3. 打开“修复建议”，展示模型对数量下界和加法错误的逐文件解释；切换 `quantity.cj`、`fee.cj` 展示实际候选源码及差异。
4. 打开“验证报告”查看9项实际用例；看完源码后由演示操作者点击“接受”，再下载同版本源码与证据。
5. 依次展示三个订单及三个跨文件案例。每个案例有独立原始源码、需求映射与测试。点击“开始”才请求模型，会产生费用；未生成时右侧没有固定修复代码。
6. 选择“测试保护拦截”“配置保护拦截”“路径越界拦截”任意一个并开始，观察真实原生策略拒绝、候选写入数零；这些受控探测不调用模型，不导出。
7. 展示任务记录与交付包。历史模式继续保留，标签“回放”“模拟”表明来源，不作为本次 AI 修复证据。

模型调用失败时查看执行记录，不能解释为通过或静默切换成预置答案。一次任务最多三轮、每轮一次模型请求；只有真实候选验证失败才进入下一轮，模型超时不重放。CEGIS 卡片可查看每轮建议、差异和 MCP 失败反馈；历史候选仅供查看，通过候选等待人工接受。明确开始新任务会重新计费。测试通过仅覆盖当前冻结行为。


## 源码分析补充演示

1. 打开“源码分析”→“直线依赖”：5个变量切片、14节点／17边，来源“样例快照”。选择 `c@sum3`，核对返回高亮行；点击图上带L3的节点关联源码。
2. 切换“循环累加”：DDG依然可见（14节点／31边），静态切片显示“日志解析恢复”、4变量；切换“跨函数调用”显示10变量，选择index@aggregate检查提示色高亮。整体仍为“部分结果”，证据中保留原切片FAILED及单独的本地派生来源。
3. 上传 `fixtures/analysis/upload_pricing.cj`，确认旧图、切片和统计清空；勾选发送至课题组MCP，再点“分析”。已实测返回4个切片变量、11节点／14边，变量名变成netPrice、charge、finalAmount对应结构。
4. 打开“证据”看SHA-256、原始记录摘要和适用范围；下载ZIP核对同一份输入与工具响应。
5. 服务重启后直接从“最近分析”恢复当前浏览器会话的上传结果，不产生新的工具调用。“重新分析”会创建新分析任务，各工具再调用一次；它不调用本地DeepSeek修复流程。
