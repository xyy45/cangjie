# MCP 原生七类图展示

用户已批准整行原生SVG方案，并要求在cangjie_cup加入接口支持的全部图类。

范围：Cfg/Cg/Cdg/Ddg/Pdg/Sdg/Dfg。保留原生SVG字节，后端同源限额获取、绑定源码／分析／原响应；前端以img加载，禁止将上游SVG作为HTML插入。图类型独立，不用另一类图代替失败类型。JSON与PDG切片算法、修复及验证不变。原Cg URL与旧记录继续读取；没有保存对应原图的历史记录说明重新分析，不制造原图。

方案：采用MCP SVG作为主图，保留JSON作为交互／切片依据。曾考虑仅修改自绘图布局，但不能满足用户直接展示MCP原图的意图；删除JSON会丢失行号切片，故不采用。原生图通过七按钮切换，占完整一行；默认全图适配，图内无滚动条；放大后拖拽，支持全屏与下载。延续浅色字体、边框和色彩，不引入前端依赖。

每图最多2MiB，总下载最多8MiB，整组SVG下载总时限30秒；相同图类冲突地址、非同源／重定向／异常XML／实体声明／凭据回显均拒绝。失败不自动重试。7类请求使用显式列表，缓存profile7；旧profile6请求幂等可读，但不能作为新结果复用。原始响应及各SVG均可导出，读取与下载前校验其绑定和字节。

只修改桌面cangjie_cup的相关文件，不修改旧工程、旧原件或密钥，不重发模型请求。独立副本测试；真实联调最多一份自建仓颉源文件的一次完整MCP分析（三工具POST及最多七SVG GET），DeepSeek请求0。完成后仅在主服务空闲且数据核对通过时切换服务。

不声称每份仓颉源码都能生成七类非空图。实际工具输出决定可用／空图／不可用；不将本地构造的测试图冒充MCP实测。
