# 上传单文件修复验收

日期：2026-10-20。范围：用户批准的上传单文件＋确认示例＋MCP／DeepSeek／CEGIS＋人工审阅与下载。

## 使用

1. 侧栏“上传文件修复”，选择UTF-8 `.cj`（64KiB／1000行），填写期望行为。
2. “读取函数”进行本地受限检查，不发模型或MCP请求。选择待测函数。
3. 填写2至12组 `args`／`expected`／`suite` JSON；target和regression各至少一项。初始expected为null，必须由用户提供真实预期，系统不会从缺陷代码猜答案。
4. 确认预期值与发送许可，冻结测试并进入工作台。点击“开始”才发送源码、需求和公开示例至课题组MCP及DeepSeek。
5. 候选经原生策略、实际编译与测试，失败反馈进入下一轮，最多三轮。通过后等待人工接受；接受后导出源码和绑定证据。

示例：[上传函数](../../examples/upload_order_functions.cj)、[六组确认示例](../../examples/upload_order_functions.examples.json)。上传准备与测试确认见 [截图](upload-repair-confirm.png)。

## 支持边界与绑定

- Int64／Bool普通函数，最多4参数、16函数；局部变量、算术／比较／逻辑、if/else、while、签名类型匹配的同文件调用。纯数值和布尔示例，不接受任意测试源码。
- 拒绝导入、类、宏、字符串、数组、成员访问、外部调用、重载、main和标准IO预留函数名；只支持LF／CRLF，不支持嵌套块注释。完整受限语法和基本类型检查同时用于原源码、模型候选和执行前复核，不能依靠注释关键词过滤绕过。
- 缺少package时仅在工程副本前置固定声明，原始上传字节不修改。候选保持所有函数参数类型、返回类型与包名。模型不能改系统生成的测试和工程配置。
- 源码、示例确认摘要、需求、冻结验证计划、基线、候选树与验证器身份相互绑定；失败／环境未知不冒充通过。生成的工程仍受既有本机原生沙箱、超时、输出上限及三轮预算约束。本功能不接收任意仓颉工程。
- 字节读取不归一化CRLF，模型before_hash绑定实际基线；诊断显示的行号属于封装后的工程副本，原始文件与前置包声明记录可在证据中区分。
- 上传记录、任务／候选／分析／agents记录和导出按浏览器会话隔离。准备和确认幂等，确认后更换示例需要重新上传；恢复页面不重放模型请求。
- 交付新增 `evidence/upload-original.cj` 和 `evidence/upload.json`，保存原始字节、文件名、原始摘要、包声明前缀及确认示例。
- 验证器升级后历史报告不重写，旧检查可能显示未知；最新匹配报告用于审阅和展示。未为旧任务自动重新调用模型。

## 原生集成与审查

SDK集成测试分别覆盖带package的CRLF文件和无package文件。测试夹具第一轮生成错误减法，真实SDK得到 `fee(3,100)` 预期300、实际-97；第二轮反馈驱动修复为乘法，实际测试通过，人工接受以 TEST_FIXTURE 标识完成测试归档，并核对原件及确认示例。这里的模型HTTP使用MockTransport，不计为真实模型迭代。

独立审查确认跨会话读取候选、影响对比、证据、agents事件，以及accept/reject/export均为404。对名称和参数个数相同、类型不同的标准库重载疑点进行了原生探针，确认仅按名称检查不足；已改为两遍签名收集和原始类型匹配，并禁止标准IO预留名。攻击回归先失败后通过，独立复核无剩余具体绕过发现。
