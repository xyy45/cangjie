# 选行切片与修复影响对比

日期：2026-10-20。

## 使用方式

源码分析：上传 `.cj` 或选择样例，点击源码行或输入整数行号，再点击“分析”。当前提供 SymPas 后向切片；不是点击行就自动调用远端。界面分别标明待请求目标和当前结果的准则，改变目标后不会把旧结果标成新结果。历史列表显示 L 行号，恢复和下载保留原参数；旧记录以原有默认准则读取，不覆盖原始证据。

修复工作台：选择实际候选，点击“影响对比”先看本地改动、函数位置和前后源码，再明确点击“生成工具对比”。分析覆盖本候选编辑文件的基线与候选两侧；请求点取各侧首个修改行，纯插入／删除取相邻有效行。每侧调用三项已接通 MCP 工具。相同文件名、源码字节和准则的已记录分析可以复用，失败／未知结果也不会自动重发。查看与重新打开报告不触发新工具请求，不调用 DeepSeek。

每任务候选最多三份生产文件；每份文件限制64KiB／1000行。新增独立候选对比一次最多18项工具请求，按实际复用减少。当前工具每请求最多45秒，无自动网络重试。全局分析名额由SQLite事务协调；影响分析的内部预约不能由网页上传请求提供。

## 结果含义和证据

- 两侧分别绑定 candidate ID、基线树摘要、候选树摘要、文件字节 SHA-256、分析 ID 和切片准则；不按不稳定的节点ID跨版本匹配。
- 修改行按文本 diff 对齐；函数范围通过屏蔽字符串／注释后的源码文本定位，不冒充编译器 AST。
- 依赖图取包含最多修改行节点的有效 DDG，显示修改行节点及一跳邻接，最多80节点／300边；多图和截断均标明。返回失败、空图或没有对应节点时展示原因，不补造关系。
- 可从某侧打开原图与切片，明确标为修复前基线或修复后某轮候选，只读。下载包含报告、原源码、原始工具记录和逐文件摘要。
- 完成的报告状态与任务归档事件在一个SQLite事务提交；提交未确认或进程重启留下 IN_DOUBT，不自动重跑。交付时会校验已记录影响报告和原始证据，随任务归档。
- 原工程、候选源码、冻结测试、模型预算及人工接受流程不变。静态关联不证明修复正确。
