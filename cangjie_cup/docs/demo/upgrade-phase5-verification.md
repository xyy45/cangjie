# 第5阶段：仓颉原生核心强化

状态：已完成本机验收。最终发布防护及无参数兼容性修正后的完整回归通过；进入第6阶段。

## 当前实现

新增 `cangjie/core/src/main.cj`，使用固定仓颉SDK1.0.5和已有stdx真实编译。三个JSON行IPC操作为 `boundary.axes`、`policy.decide`、`task.transition`。Python负责可信事实、存储和进程控制，仓颉负责轴计算与许可／转换决策。

- 原生边界轴支持Int64和Bool，稳定顺序、去重、上下界／临界点邻近值与极值前置检查。生产独立搜索与缩减使用本次原生轴；组合、随机、附加缩减值和封存输入过滤仍为Python。未声称穷举所有业务语义。
- 新活动MCP和所有现有策略探测明确使用core2：检查实际allowed_paths、重复／保护路径、状态、任务／树／版本事实和导出审批覆盖的候选、需求、验证计划、check_set及期限。不可用时不退回policy1.1。
- IPC限定输入／输出各64KiB、原生进程总预算2秒；校验严格版本与字段、请求／载荷摘要、单行响应、退出码及组件前后身份。摘要由服务计算、原生核回传绑定，不声称原生签名或原生SHA实现。
- 构建元数据绑定全部原生源（当前仅main.cj）、二进制与编译器。独立报告保留完整native_boundary请求／响应及组件摘要，verify和交付重放核验。schema1、schema2活动验证计划均绑定新组件，旧组件下审批须重新验证；原记录保留可读。
- 状态转换原生检查后，在短SQLite写事务中校验完整任务快照和完整原生proof再提交。候选入口校验调用方快照，复制后登记候选／attempt采用同一事务；循环claim、取消／拒绝、导出预留／发布、重启恢复均走同一提交入口。原生进程不在写事务中运行。
- READY保留显式手工SDK验证流程，因此允许由服务推进至验证／待审阅；该许可不是测试通过证明，接受与交付仍要求真实check_set。终态不允许复活或增加尝试预算。重启时先在事务外取得可能状态的许可，再按事务内最新未完成操作选择结果，不重放模型请求。
