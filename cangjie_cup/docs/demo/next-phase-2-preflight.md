# 第2项实施前准备：组合业务规则难例

2026-10-25，只读代码调研和后续设计准备。第1项最终验收尚未结束；本文不代表第2项产品功能、数据或模型评测已经完成。

## 已核实的接入点

- `nexus/benchmark/corpus.py`当前只接受30／100任务，固定generator版本。新增10任务不能简单改清单数量或把旧数据重新命名；需要明确的新语料版本及完整加载校验。
- 原有语料已分公开需求／例子、独立搜索规则、封存holdout、参考修复。v2搜索规则用类型化excluded_inputs排除最终验收输入，缩减也不能触碰holdout。
- `quality.py`实际仓颉SDK门禁按10任务一组执行baseline/reference，要求缺陷可编译且被holdout击穿、参考修复公开／封存都通过，并保存工程manifest、执行命令、完整日志及hash。它检验语料有效性，不能当模型修复效果。
- CLI已有只读plan、串行run、遇未知停止、完整计划分母和可重放报告；新的实际运行必须冻结执行身份并申请新预算。
- 新阶段继续使用Int64／Bool、同包、最多3个允许修改生产文件；暂不把字符串、数组、数据库或并发状态混进当前语料。

## 初批10个不同候选（尚未生成／验证）

| 候选 | 组合规则与主要缺陷 | 重点边界 |
|---|---|---|
| 累计退款上限 | 退款必须为正、历史累计合法、本次不超过剩余实付；非法保持原状态 | 已全额退款、刚好剩余、超过一分 |
| 优惠叠加顺序 | 按确认的顺序执行折扣与满减，折后不小于零 | 刚好门槛、折后跌破门槛、优惠大于原价 |
| 手续费向上取整 | 正金额按基点计算后向上取整，受最低及最高收费约束 | 不能整除、上下限相遇、零金额 |
| 库存预留与释放 | 扣减需正数且不过量，释放不得超过预留，非法操作保持库存 | 零、负数、刚好可用、释放超量 |
| 分期尾期补差 | 前期使用明确整数规则，最后一期承担剩余，累计等于总额 | 不能整除、期数1、最后一期 |
| 包邮与优惠组合 | 以确认的折后金额判断包邮，阈值包含等号 | 折前达标折后不达标、刚好阈值 |
| 积分兑换双上限 | 兑换同时受积分余额和订单可抵扣上限约束，余数不可多抵 | 少于一个兑换单位、恰好上限 |
| 整数极值安全计价 | 先验证非负及乘法安全，再计算合计；非法返回明确值 | Int64边界、乘积溢出、负数 |
| 三函数跨文件计费 | 校验、基础计费与附加费共享一致业务规则 | 上层校验与下层边界不一致 |
| 阶梯费率与封顶 | 分段增量计费后封顶，不将整个数量套用最高档 | 各档前后、恰好封顶、超过封顶 |

这些是团队自建组合规则候选，不预称“真实生产漏洞”，也不预称比旧数据更难。先通过质量门禁，再以模型实际首轮遗漏、独立搜索反例和后续修复记录衡量难度。
