# 第3B项实施前调研：成对调用关系

2026-10-26。3A已验收并加载8877；3B尚未实现。真实模型／远程分析预算0，沿用既有持续实施授权，不重复常规阶段确认。没有启动医疗HW Autopilot。

## 现状与接入点

3A已经提供单次属性契约、用户确认、受限副本、原生参数轴、SDK实际返回观测、CAS与重放、CEGIS反例、定位、审批归档及前端。真实SDK已覆盖128次调用、零参数、Bool和Int64下界；因此成对观测可复用同一批次中的两个独立case，不需要扩大仓颉语法或执行命令。

当前`property_trace.py`将通用SDK观测协议和单次断言解释放在一起；`properties.py`的表达式类型器可以核对任意有界名字映射，但别名／参数组合仍为单次语义。`PropertyService`不能仅改标签就成为关系引擎：它缺少输入对、两侧原件绑定、保留输入双侧过滤、关系前置条件和关系反例缩减。

上传确认目前将oracle与properties分别冻结，properties空字段不改旧哈希。候选测试顺序为公开→oracle→single；增加relations必须在前面必需检查通过后执行。控制器、交付与当前候选摘要必须显式消费新结果，不能只添加页面。

## 采用的方向及取舍

1. 只验证同一个已确认函数的输入对，以前置条件描述两侧参数关系，以断言比较两侧实际返回。复用现有AST和原生轴，独立`relations_json`确认／文件／报告；最符合当前有限纯函数范围，并允许与single同时启用。
2. 用户编写任意变换代码，或者开放测试源码：会扩大未授权执行面，不采用。
3. 为每种单调性／缩放关系写固定修复案例：覆盖窄、难以表达业务适用条件，不采用。

这是实现方在已有路线内作出的选择，未声称用户逐字段选定了契约。设计将保留自定义有界关系表达式，不只支持固定单调性案例；也不把关系误用到含优惠等不满足前提的场景。

## 必须控制的风险

- 同一输入可出现在两侧或多个输入对中，每次观测仍独立执行，不能借单次缓存伪称两次调用。single现有去重限制保持。
- 任一侧命中保留集合，整对不得执行／累计／缩减；三个契约共存时确认相同的完整排除集合。
- 关系前置条件全部不适用不能PASS；缺一侧、错nonce／类型／树或解释异常均为UNKNOWN。
- 缩减必须保持原失败关系前提，并重跑两侧；需要协调缩减相等的参数，不能通过改变固定价格破坏前提。
- 反例具有两个真实返回和一个false关系结论，不能编造单个数值expected。定位两个实际调用到同一冻结基线，保留各自失败版本与原件位置。
- 大Int64继续由服务端附带规范展示文本，当前报告重新verify；历史事件不能单独升级为当前PASS。
- 不变更SDK／core／外部依赖；不复用已关闭的真实模型额度，不把HTTP夹具写成模型能力。

详细契约与算法见后续设计；3B通过后才设计3C操作序列。
