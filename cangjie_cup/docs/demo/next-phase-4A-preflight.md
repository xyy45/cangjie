# 第4A项字符串支持：实施前调研

状态：仅调研；3C现已验收并激活，本阶段尚未开放上传字符串修复。沿用持续开发授权，不新增模型或远程分析预算。

## 当前工程事实

`nexus/uploads/language.py` 以受限词法／递归解析检查普通函数，拒绝字符串、成员访问和导入；不是SDK AST。`literal`、公开测试、oracle表达式／域、properties、relations、sequences与primitive观测目前限定Int64／Bool。不能仅放开上传类型名单。

## 固定工具链实验

在独立自建目录中运行固定SDK 1.0.5：`cjpm test --no-run` → `cjpm test --skip-build --show-all-output`，退出0，1个case／16个断言通过。原件见[实验目录](validation/next-phase-4A-preflight/manifest.json)。没有调用模型、远程分析或改动3C冻结源码。

实际观察：`.size` 是UTF-8字节数，中文“中”为3，😀为4；`.toRuneArray().size` 统计Unicode码点，`e`加组合重音是2，预组合é是1，二者比较不相等。未做规范化，不承诺用户感知字素数量。空串、拼接、相等和ASCII大小比较通过；`toArray()`实际遍历得到7个“中😀”字节。Unicode转义美元符不会触发字符串插值；NUL、换行、回车、tab、引号、反斜杠均已在自建case验证。

官方[字符串接口文档](https://docs.cangjie-lang.cn/docs/1.0.0/libs/std/core/core_package_api/core_package_structs.html)作为背景说明，1.0.5直接文档地址本次工具无法读取；以上支持判断以本地固定1.0.5实际编译执行为依据。

## 下一阶段必须决策和覆盖的范围

1. 字符串值有界（建议每值256 UTF-8字节），拒绝非法Unicode代理字符。长度规则明确区分字节和码点，不默认规范化。
2. 源码只增加普通字符串字面量／拼接／相等和受限长度访问；拒绝插值、任意成员、反射、构造或导入。值转源码使用逐码点Unicode转义，避免模型或测试输入变成可执行语法。
3. 公开测试、规则／属性／关系／状态模型分别明确支持范围及版本；字符串不能靠旧Int64／Bool解码器解释。旧契约、正常harness和旧封存必须仍可复验。
4. 观测使用有界UTF-8字节编码，不把原文直接拼进日志协议；覆盖分隔符、换行、保留标记、Unicode和输出超限。
5. 搜索／缩减、历史反例、反馈／定位、审批／下载与前端都绑定同一类型语义；不同阶段未支持的组合应拒绝，不能声称全链支持。

这是可行性材料，不是设计批准或产品完成记录。3C验收后按总目标写独立设计／实施计划，并明确剩余组合和兼容成本。
