# 同包两文件计费修复

此工程未注册到内置案例列表，通过用户上传接口导入。两个生产文件分别有多收费错误，原测试分别检查入口函数和被调用函数。正确实现是fee返回amount，total调用fee后加100。

1. 打开“上传文件修复”，导入方式选“仓颉工程 ZIP”，选择本目录billing.zip；或选“仓颉工程目录”，只选择project子目录。
2. 用“导入文件”填写goal.txt，再点击“读取函数”。
3. 检查工程文件树，勾选src/fee.cj和src/order.cj；待测函数选total。
4. 导入tests.json和可选oracle.json，核对后勾选确认并进入工作台，点击“开始”。
5. 查看普通测试、独立搜索和每轮修复；通过后人工审阅接受，再下载交付包。交付含原ZIP／文件、原配置与测试、候选、日志和规则证据。

真实模型可能一轮修好，也可能失败，不保证固定轮次。三轮集成测试使用确定性模型HTTP响应验证状态流转，SDK、策略、构建与运行均实际执行。

首版工程范围：一个cjpm静态包，固定1.0.5 SDK，无外部依赖或build.cj；src直属Int64／Bool普通函数。同包函数可跨文件调用；原测试限标准@Test类、@TestCase零参方法中的单条字面量@Expect。允许修复1至3个生产文件。上传上限和语言限制由服务端执行。

生成归档：在此目录运行 `python3 -m zipfile -c billing.zip project`。只打包project，不把本目录中的规则和说明作为工程源码上传。
